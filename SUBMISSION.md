# Data Analyst — LLM-агент для перевірки та очищення таблиць

## Задача

Data Analyst допомагає дослідити якість даних у CSV та Excel: знайти пропуски, дублікати, зайві пробіли, неоднорідні категорії та проблеми перетворення чисел і дат. Агент ставить уточнювальні запитання, коли виправлення залежить від значення даних. Наприклад, від’ємна сума може бути коректним поверненням, а однаковий номер бронювання — кількома різними позиціями.

## Як працює агент

LLM отримує завдання користувача й описи доступних інструментів. Модель повертає структуровані виклики функцій, застосунок виконує їх у Python і надсилає результати назад моделі. Агент використовує результати для наступного кроку або відповіді користувачу. Це власний варіант задачі, дозволений умовою, а не реалізація прикладів Software engineering agent чи AI Examiner.

## Інструменти

| Інструмент | Призначення |
|---|---|
| `profile_table()` | Розміри таблиці, типи колонок, пропуски, повні дублікати та приклади значень. |
| `inspect_rows(column, query, limit)` | Пошук конкретних записів і показ обмеженої вибірки. |
| `check_column(column)` | Перевірка пробілів, нечислових і від’ємних значень, частот категорій. |
| `aggregate(group_by, value, method)` | Групові суми, середні, кількості, мінімальні та максимальні значення. |
| `propose_plan(operations, explanation)` | Підготовка плану та попереднього перегляду змін без застосування. Операція `drop_rows_where` видаляє рядки з точним збігом значення у вказаній колонці або в будь-якій колонці, якщо її не вказано. |

Усі інструменти виконуються локальним Python-кодом. Перевірка колонок не є універсальним валідатором усіх типів даних: агент поєднує статистику, вибірки та уточнення користувача. Невалідні перетворення чисел і дат відхиляються під час підготовки плану.

## Інтерфейс та контроль змін

Вебінтерфейс побудовано на Streamlit. API-ключ Groq вводиться в приховане поле; застосунок не записує його у вихідний код чи конфігурацію. Без ключа немає режиму імітації роботи LLM.

Застосування плану доступне лише через кнопку підтвердження користувачем. Перед цим показуються змінені й видалені рядки та повна таблиця-кандидат. Є відхилення плану, відкат останніх п’яти станів, збережений у пам’яті оригінал, графіки та експорт CSV, XLSX і JSON-звіту з діалогом та журналом успішних викликів інструментів.

Під час обробки та автоматичних повторних спроб показується «Думаю…» без таймера. Тимчасові ліміти провайдера обробляються обмеженими повторними спробами; немає нескінченного очікування. Попередні результати інструментів прибираються з контексту наступних ходів, а уточнення користувача та поточний стан зберігаються.

## Запуск

Потрібен Python 3.11+ та API-ключ Groq із доступом до openai/gpt-oss-120b.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m streamlit run app.py
```

Запустити команду вище з папки проєкту. Локальна адреса — http://localhost:8501. Ввести ключ, дозволити передачу зразків даних Groq, завантажити таблицю й почати діагностику.

## Обмеження

Ліміти таблиці: 10 МБ, 20 000 рядків, 60 колонок. Excel читається як значення першого аркуша; форматування та формули не переносяться. Дані, ключ і журнал зберігаються в пам’яті сесії, тому перед її завершенням потрібно завантажити результат. Частини таблиці надсилаються обраному LLM-провайдеру за згодою користувача. Ліміти API та помилки моделі залишаються зовнішніми обмеженнями; результати потребують перегляду користувачем.
